## Risks
- The before-run (step 2) may be green on today's main: PR #53 already awaits the engine-side sites and the intent's 2-of-3 observation predates it. The change is still required because the three `void` sites in http.ts (lines 49, 588, 619) are a fatal unhandled rejection in a real `sdlc serve` process; the before/after pair is recorded either way (spec C2). If the before-run is red for a different reason (5 s timeouts, load over 200), say so and rerun the failing file alone rather than attributing it to this defect.
- Test (a) depends on `GitError`'s message starting with `git ` (adapter-git `git.ts:16`). `gitRaw` never rejects, so even a missing cwd becomes a GitError (code coerced to 1, empty stderr). Removing only `.git` gives the deterministic "fatal: not a git repository" text.
- Test (b) depends on `close()` setting `closed = true` synchronously before its first await (engine.ts:114) and on `onSessionExit` being called directly (not via `track`), so `close()` has nothing outstanding and resolves at once. If a future change makes `close()` await before flipping the flag, (b) will claim a job; that is the regression the test is for.
- The `refresh` step check in the four record/mirror helpers changes their return value from the job to `null` when the engine closed after the write. Nothing on the exit path reads that value; the manual path (`runForChange` → `runForSession(…, "manual")`) never runs on a closed engine. If the build finds a caller that does read it, return `this.opts.jobs.get(key)` there instead and say so in the commit.
- Spec C4's `failed: engine closed before <step>` state is reached only if a write throws during close; with no await between `jobs.claim` and the write, a close cannot strand a job in `running`. Do not add a check there.
- `.sdlc-state/worktrees/*` sessions have no node_modules; the Stop-hook round is red for environment reasons unless step 1 ran. The ledger round must come from the installed worktree (spec C12).
- Full-suite runs from two worktrees at once produce timeouts unrelated to this change; check load and other vitest processes before repeating.
