# Plan: Cybercab step 6 — finish Pipeline, Gates, Loop, Security and Metrics to the handoff (from spec.md 37e1f12)

Rewrite of five view components, their CSS and the render test so the views match `sdlc/changes/CHG-0001/design/README.md` line for line (spec R1–R12). Data, routes and callbacks do not change. Every step below is one commit; the commit message is the step's first line. `pnpm test` is green after every commit because each step carries the test edits for the strings it removes.

Decisions this plan makes on the spec's open concerns (none was resolved at gate 2; each is a one-line change if the owner decides otherwise):
- C1/C2: the done signal is the selector grep `grep -rnE '\.chip|"chip|chip[ "]' packages/web/src` → empty. `--radius-chip` (a §6 token, unreferenced) and `record.chip` in `lib/format.ts` (a core field) stay. The tokens.css comment on line 105 is reworded so the literal `grep chip` returns only those two lines.
- C3: `app.tsx` and `lib/format.ts` are in the file list.
- C4: no `it` block is deleted; every dropped assertion is replaced in the same `it` by the handoff replacement string (named per step).
- C5: commit messages are `sdlc(web): <removals-log line>`; additions that are not removals use the same prefix with a plain description.
- C6/C10: follow the handoff — the agent word leaves Pipeline line 1 (edge + pulse carry it; line 3 keeps `c.status`), trends render `▲`/`▼`.
- C7: `docs/decisions.md` gets one appended row (step 24) saying rows 3.4 and 3.6's rendering is superseded; the old rows are not rewritten.
- C8: evidence `<pre>` keeps content, `white-space: pre-wrap`, `max-height: 220px; overflow: auto`; only background and padding go.
- C9: one scoped rule `.security .item:not(.new)::before { box-shadow: none; }`; no new utility class.

Shared predicates (define once, reuse in Pipeline and Gates):
- `owned(c, role)` = `c.valid && (c.gate ? c.gate.ownerRole === role : c.deploy.productionGate?.open === true && c.deploy.productionGate.ownerRoles.includes(role))` — the same predicate as `gateQueues` in `packages/core/src/queues.ts`.
- `hasOpenGate(c)` = `c.valid && (c.gate !== null || c.deploy.productionGate?.open === true)`.
- `OTHER_ROLES: Record<Role, string>` = `{ po: "the engineer or tech lead", eng: "the product owner or tech lead" }` (new export in `lib/format.ts`).
- Headline number word: `n === 1 ? "1 decision waits" : \`${n} decisions wait\``; same pattern for `signal(s)` and `finding(s)`.
