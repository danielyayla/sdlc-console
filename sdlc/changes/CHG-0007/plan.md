## Risks

- **This change's own sessions start bare (C9).** The plan and build sessions run under the console on `main`, which does not have this change. The engineer runs the R3 pnpm command by hand in the build worktree before anything else; without it every verify round is red for the reason this change fixes. The green first round the intent asks for is observable only on the first session launched after merge and a console restart.
- **Native module under pnpm 10 (C4).** `better-sqlite3` needs its prebuilt binary; pnpm 10 skips dependency build scripts unless allowlisted and this repo allowlists none. A by-hand install in a worktree produced a green 553-test run for CHG-0002, so the binary arrives without a build script on this machine; the R12 check `node -e "require('better-sqlite3')"` in the fresh build worktree is the proof, pasted. If it fails, the fix is `pnpm.onlyBuiltDependencies` in `package.json`, a file outside this plan — stop and send that back rather than widening the change silently.
- **Manager on PATH, corepack (C3).** `packageManager: pnpm@10.12.4` is declared; if the PATH pnpm differs and corepack is active, corepack may try to download that version, which needs the network. The console records whatever happens and refuses the launch with the output; that is the operator's environment, as with `pnpm build` by hand. Not mitigated in code.
- **Concurrent launches share the pnpm store.** Two sessions preparing worktrees at once serialise on the store lock; the 10-minute timeout covers a slow first install (the plan session's by-hand install of this repo takes well under a minute from the store).
- **The 502 is thrown before the record exists**, so the Sessions view cannot show the failed install's output on a card (there is no card). The output reaches the HTTP body, the CLI's stderr and the engine job's one-line `error`; `install.log` is not written for a refused launch because there is no session directory yet. A reviewer who wants the failure on a card would need a record for a session that never started, which R6 rules out; the plan keeps the spec's reading.
- **`sessionStart` now catches every `ActionError`.** Exit code stays 1 for all of them (the generic path already returned 1); the only visible change is that diagnostics print. No test asserts the bare form.
- **Real-shell tests depend on `/bin/sh` and a writable temp dir**, both true on macOS and Linux CI. The `sleep 5` timeout case costs 200 ms, not 5 s (the child is killed).
